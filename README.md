# Combining Hierarchical Structure and Semantic Retrieval in Financial RAG Systems

This repository contains the code, data metadata, and evaluation scripts used for the master thesis **“Combining Hierarchical Structure and Semantic Retrieval in Financial RAG Systems”**, conducted at Erasmus School of Economics, Erasmus University Rotterdam.

## Overview

This research investigates whether incorporating document hierarchy can improve retrieval quality in Retrieval-Augmented Generation (RAG) systems for long and complex financial documents.

The following retrieval approaches are compared:

- **BM25** – lexical retrieval
- **Dense retrieval**
  - Harrier-OSS-v1-0.6B
  - Linq-Embed-Mistral
- **PageIndex** – hierarchical retrieval using LLM-guided navigation
- **Hybrid PageIndex** – hierarchical retrieval using semantic embeddings instead of LLM-guided navigation

The proposed Hybrid PageIndex retains the hierarchical document structure generated by PageIndex, but replaces LLM reasoning during navigation with embedding-based similarity.

Two Hybrid PageIndex variants are evaluated:

- **Node-only retrieval** – candidate nodes are selected based on their node representations.
- **Chunk reranking** – retrieved candidate leaf chunks are reranked using chunk embeddings.

For Hybrid PageIndex, beam widths of `m = 5`, `m = 7`, and `m = 10` are evaluated.

## Research Questions

The main research question is:

> To what extent can structure-based retrieval improve retrieval quality in Retrieval-Augmented Generation systems for complex financial documents?

The analysis addresses three sub-questions:

1. How do lexical, dense, and structure-based retrieval paradigms compare with respect to retrieval quality?
2. Can combining hierarchical document structure with embedding-based semantic retrieval improve retrieval performance compared with flat dense retrieval?
3. What are the computational trade-offs between retrieval quality and efficiency across lexical, dense, structure-based, and hybrid retrieval systems?

## Datasets

Two financial datasets are used.

### ESRS Banking Dataset

The first dataset consists of selected ESG-related sections from the 2024 reports of 23 major European banks.

The original PDF reports are **not redistributed in this repository**.

The file:

`data/esrs_bank_page_ranges.csv`

contains the bank name, original PDF name, and page range(s) used for each report.

The resulting dataset contains:

- 3,935 pages
- 2,968 raw chunks
- 2,962 unique canonical retrieval chunks
- 1,924 chunks eligible for query generation
- 1,000 synthetically generated question-answer pairs

The questions were generated using GPT-5 and are evaluated in a single-hop setting with one annotated ground-truth chunk per query.

### FinanceBench

The second dataset is based on the publicly available FinanceBench benchmark.

After restricting the evaluation to single-hop questions that could be matched to one retrieval chunk, the final evaluation set contains:

- 65 financial documents
- 8,624 pages
- 7,432 raw chunks
- 7,426 unique canonical retrieval chunks
- 111 question-answer pairs

## Evaluation

Retrieval performance is evaluated using:

- **Accuracy@1**
- **MRR@5**

Additional analyses examine:

- document-level retrieval performance
- table-of-contents availability
- FinanceBench query characteristics
- PageIndex retrieval behaviour
- Hybrid PageIndex beam-width sensitivity
- node-only retrieval versus chunk reranking

Efficiency is evaluated using preprocessing latency, query-time latency, and LLM token usage.

An end-to-end evaluation is also performed in which GPT-5 generates answers using either the Top-1 or Top-5 retrieved context. The generated answers are evaluated using an LLM-as-a-judge framework.
